# Image Precaching System

This directory contains tools for managing the service worker's precache manifest, ensuring that responsive image variants are cached for offline use.

## Overview

The service worker precaches assets so the PWA can work offline. For images, we need to precache not just the base images referenced in `menu.json`, but also the highest-resolution responsive variants generated by `tools/process-images.js`.

## How It Works

### 1. Image Processing
- `tools/process-images.js` generates responsive image variants from source images
- Variants are created at multiple widths (640w, 1280w, 1920w, 2560w) and formats (AVIF, WebP, JPEG)
- Variants are stored in `public/images/{slug}/` with manifest files

### 2. Precache URL Generation
- `tools/generate-precache-urls.js` reads `menu.json` and scans `public/images/` manifests
- Extracts all image URLs including:
  - Base images from menu items (`image` field)
  - Srcset variants from menu items (`imageSet` field, when present)
  - Highest-resolution variant for each format from manifest files (by default)
- Outputs to `scripts/precache-images.js` (auto-generated, gitignored)
- Injects the image array into `service-worker.js` between markers

### 3. Service Worker Integration
- `service-worker.js` combines `CORE_PRECACHE_URLS` with `MENU_IMAGE_URLS`
- During install, all URLs are precached for offline access
- The `MENU_IMAGE_URLS` section is auto-generated (between markers)

## Build Process

Run this after generating images or updating menu.json:

```bash
npm run build:precache
```

This runs `node tools/generate-precache-urls.js --only-highest` to cache only the highest resolution variant per format, keeping the precache size reasonable.

This is automatically included in:
```bash
npm run check:all
```

### Advanced Options

To cache ALL variants (not recommended for production due to size):
```bash
node tools/generate-precache-urls.js
```

Default (recommended) behavior with `--only-highest`:
- Caches ~82 images (22 base + 60 highest-res variants)
- Each image gets its highest available resolution in AVIF, WebP, and JPEG formats

Without `--only-highest`:
- Caches ~340 images (all widths × all formats)
- Much larger initial download but guarantees all variants are available offline

## Testing

Test the precache system:
```bash
npm run test:precache
npm run test:sw
```

Tests verify:
- High-resolution variants (1280w, 1920w) are included
- Modern formats (AVIF, WebP) are included  
- No duplicate URLs
- Service worker correctly uses generated URLs

## File Structure

```
tools/
  generate-precache-urls.js    # Extracts image URLs and updates SW
  process-images.js             # Generates responsive variants

scripts/
  precache-images.js            # Auto-generated URL list (gitignored)

public/images/
  {slug}/
    manifest.json               # Metadata for generated variants
    {slug}-{aspect}-{width}w.{format}

service-worker.js               # Uses MENU_IMAGE_URLS for precaching
```

## Adding New Images

1. Add source image to `assets/photos/`
2. Run `npm run build:images` to generate variants
3. Update `menu.json` with the image path
4. Optionally add `imageSet` with specific srcset entries
5. Run `npm run build:precache` to update precache manifest
6. Test offline functionality

## Markers in service-worker.js

The service worker has special markers for auto-generation:

```javascript
// MENU_IMAGES_START - Auto-generated by tools/generate-precache-urls.js
const MENU_IMAGE_URLS = [ /* auto-generated */ ];
// MENU_IMAGES_END
```

**Do not manually edit** the content between these markers—it will be overwritten.

## Rationale

The `--only-highest` approach ensures that:
1. Users on high-DPI displays get the best quality images
2. The browser's srcset mechanism can still select appropriate images based on viewport
3. Lower-resolution variants are cached on-demand through the service worker's fetch handler
4. Initial PWA installation size remains reasonable (~few MB vs ~32MB for all variants)
